СТРУКТУРА ПРОЕКТА И ОПИСАНИЕ ПАРАМЕТРОВ (торговая система, v1)
===============================================================

Порядок запуска:
    python3 run_pipeline.py            # единая точка входа, запускает по очереди:
    1. data_collector.py               #   собрать свечи с биржи
    2. strategy_backtest.py            #   прогнать стратегию на собранных свечах
    Каждый этап: запуск -> блокирующее ожидание завершения -> проверка результата.
    Сбой/подозрение = WARNING в logs.txt и остановка конвейера (exit code 1).

===========================================================================
РАЗДЕЛ 1. ФАЙЛЫ ПРОЕКТА (за что отвечает каждый)
===========================================================================

config.json            — НАСТРОЙКИ. Создаётся/правится вручную, читается ВСЕМИ скриптами.
data_collector.py      — ФАЙЛ 1: СБОРЩИК ДАННЫХ.
    Вход : config.json (symbol, timeframe_minutes)
    Выход: candles.csv; выполняет LOG RESET и пишет в logs.txt (тег [collector])
    Блоки кода: настройки/лог -> загрузка с биржи (ретраи, перебор хостов)
                -> сохранение. Первая строка результата — заголовок, далее
                свечи от самой СТАРОЙ к новой. При пустом ответе биржи
                старый candles.csv НЕ затирается (защита от сбоя сети).
candles.csv            — ДАННЫЕ. Создаёт data_collector.py, читает strategy_backtest.py.
run_pipeline.py        — ФАЙЛ ОРКЕСТРАТОР (точка входа).
    Вход : config.json; запускает скрипты этапов как отдельные процессы
    Выход: только дозаписывает logs.txt (тег [pipeline]); своих файлов не создаёт
    Проверки этапа collect : candles.csv существует, заголовок верный, >=50 свечей,
                             порядок old->new, low<=open/close<=high, open_time<close_time.
    Проверки этапа backtest: backtest_result.json читается и содержит обязательные
                             поля (initial_balance, final_balance, total_pnl,
                             return_percent, trades_count), trade_history.txt непустой.
strategy_backtest.py   — ФАЙЛ 2: СТРАТЕГИЯ + ТЕСТЕР (полное описание — раздел 2).
    Вход : config.json, candles.csv
    Выход: backtest_result.json, trade_history.txt, дозаписывает logs.txt ([backtest])
backtest_result.json   — РЕЗУЛЬТАТ ТЕСТА в формате JSON (создаёт strategy_backtest.py).
trade_history.txt      — ПОЛНАЯ ИСТОРИЯ СДЕЛОК + СОСТОЯНИЕ СЧЁТА в виде лога.
logs.txt               — ОБЩИЙ ЛОГ ВСЕЙ ПРОГРАММЫ. Один файл, новых не создаётся:
    collector при каждом запуске ОЧИЩАЕТ и перезаписывает его с нуля
    (первая строка LOG RESET); backtest и pipeline в рамках цикла только дозаписывают.
STRUCTURE.txt          — этот файл: инструкция структуры, принципы стратегии, параметры.

Контракт обмена между файлами (строгий, только через файлы, импортов кода нет):
    config.json  -->  data_collector.py / strategy_backtest.py / run_pipeline.py
    data_collector.py --> candles.csv --> strategy_backtest.py (+проверка pipeline)
    strategy_backtest.py --> backtest_result.json + trade_history.txt
    все три скрипта --> logs.txt
Новые модули должны читать только config.json и candles.csv и писать только
в свои выходные файлы.

===========================================================================
РАЗДЕЛ 2. ПРИНЦИП РАБОТЫ СТРАТЕГИИ (strategy_backtest.py)
===========================================================================
Тип: трендовая стратегия на пересечении двух простых скользящих средних
(SMA cross). Обе длины читаются из config.json: быстрая = fast_period (5),
медленная = slow_period (13). Средние считаются по цене close каждой свечи.

Блок А. ИНДИКАТОР (moving_average)
    По ходу прохода по свечам поддерживаются два окна усреднения:
    MA_fast(5) — реагирует на цену быстро; MA_slow(13) — эталон тренда.
    Пока окон неполно (первые slow_period-1 свечей), сигналов нет.

Блок Б. СИГНАЛ И ВХОД
    На каждой свече сравниваются значения MA "было" (prev) и "стало":
    - MA_fast была <= MA_slow и стала > MA_slow  -> пересечение вверх -> LONG;
    - MA_fast была >= MA_slow и стала < MA_slow  -> пересечение вниз -> SHORT.
    Вход исполняется по цене close текущей (сигнальной) свечи, время входа =
    close_time этой свечи (сигнал подтверждён только закрытием свечи —
    знания о будущем не используется).

Блок В. ПЕРЕВОРОТ ПОЗИЦИИ (flip)
    Обратное пересечение при открытой сделке НЕ оставляет систему без позиции,
    а переворачивает её: старая позиция закрывается по цене close сигнальной
    свечи (запись в историю), и сразу открывается позиция в новую сторону по
    той же цене. Одно пересечение = одна закрытая + одна открытая сделка.

Блок Г. ПРИНУДИТЕЛЬНОЕ ЗАКРЫТИЕ
    Если после последней свечи сделка ещё открыта, она принудительно
    закрывается по close последней свечи; в backtest_result.json ставится
    флаг forced_close_at_end = true.

Блок Д. УЧЁТ ФИНАНСОВ (make_trade)
    PnL сделки = (цена выхода - цена входа) * направление(+1 лонг / -1 шорт)
    - комиссии. Комиссия fee_rate берётся с номинала каждой стороны отдельно:
    (entry_price + exit_price) * fee_rate. Фактически одна сделка торгуется
    на весь баланс (1x, без плеча); поле backtest.position_size в config.json
    зарезервировано под будущий модуль управления размером позиции —
    текущий код бэктеста его ещё не применяет. Баланс обновляется после
    каждого закрытия; balance_after пишется в каждую строку истории.

===========================================================================
РАЗДЕЛ 3. ВСЕ ПАРАМЕТРЫ config.json (значение каждого)
===========================================================================
symbol                     "SOLUSDT"
    Тикер бессрочного фьючерса на Solana. Передаётся в запрос бирже Bibit;
    должно точно совпадать с контрактом на бирже.
timeframe_minutes          5
    Интервал одной свечи в минутах. Задаёт granularity данных и скорость
    сигналов: меньше минут -> больше шума/сделок, больше -> реже и грубее.
strategy.fast_period       5
    Длина быстрой средней кривой (окно SMA в свечах). Меньше -> чувствительнее,
    больше ложных пересечений; больше -> позже вход в тренд.
strategy.slow_period       13
    Длина медленной средней кривой. Задаёт эталон тренда; пересечение быстрой
    через неё = сигнал смены направления. Строгое требование кода: slow > fast.
backtest.initial_balance   1000.0
    Стартовый условный капитал теста (USDT). От него считаются размер позиции,
    PnL и итоговая доходность в процентах.
backtest.fee_rate          0.0005
    Комиссия биржи за ОДНУ сторону сделки (0.05%, типичный taker perpetual).
    Списывается и при открытии, и при закрытии (~0.1% на полную сделку).
backtest.position_size     1.0
    Зарезервировано под будущий модуль управления размером позиции (доля
    баланса в сделке). Текущий бэктест это поле НЕ читает — сделки идут
    на весь баланс; описание будет обновлено при подключении параметра.

===========================================================================
РАЗДЕЛ 4. ВСЕ ПОЛЯ backtest_result.json (что означает каждое)
===========================================================================
initial_balance        Стартовый баланс — копия из config.json.
final_balance          Баланс после всех сделок и возможного принудительного
                       закрытия = initial_balance + total_pnl (округлён до 4 знаков).
total_pnl              Суммарный чистый результат теста (USDT, после комиссий).
return_percent         Доходность: (final/initial - 1) * 100, %.
trades_count           Число ЗАКРЫТЫХ сделок за тест (переворот считается
                       закрытием старой сделки; открытая в конце — тоже).
wins                   Из них прибыльных (pnl > 0).
losses                 Из них убыточных (pnl <= 0).
win_rate_percent       wins / trades_count * 100 — доля успешных сделок.
forced_close_at_end    true — последняя позиция закрыта принудительно на границе
                       данных (блок Г); false — все сделки закрыты сигналами.

===========================================================================
РАЗДЕЛ 5. ВСЕ ПОЛЯ trade_history.txt (формат лога, что означает каждое)
===========================================================================
Строка 1: START BALANCE: <число> — баланс до первой сделки.
Далее по одной строке на каждую ЗАКРЫТУЮ сделку:
TRADE #N LONG|short entry=<цена> @ <время> -> exit=<цена> @ <время> pnl=<±число> balance=<число>
trade_number (#N)      Порядковый номер закрытой сделки с начала теста.
direction (LONG/short) Направление позиции: LONG — ставка на рост после
                       пересечения вверх, short — на падение после пересечения вниз.
entry_price            Цена входа (close сигнальной свечи).
entry_time             Время входа = close_time свечи сигнала (unix seconds).
exit_price             Цена выхода: close следующей сигнальной свечи (переворот)
                       или close последней свечи (принудительное закрытие).
exit_time              Время выхода = close_time соответствующей свечи (unix seconds).
pnl                    Чистая прибыль/убыток сделки (USDT, со знаком, после комиссий).
balance_after          Состояние счёта СРАЗУ после закрытия этой сделки —
                       сквозная история баланса по всему тесту.

===========================================================================
РАЗДЕЛ 6. ВСЕ КОЛОНКИ candles.csv (формат данных этапа 1)
===========================================================================
Строка 1 — заголовок. Далее свечи строго от СТАРОЙ к НОВОЙ. Колонки через запятую:
open_time    Время ОТКРЫТИЯ свечи, unix seconds (для 5m кратно 300).
close_time   Время ЗАКРЫТИЯ свечи, unix seconds (= open_time + timeframe*60).
open         Цена открытия интервала (первая цена).
high         Максимальная цена интервала.
low          Минимальная цена интервала.
close        Цена закрытия интервала — по ней считаются обе средние.
volume       Объём торгов интервала (в базовом активе, SOL).

===========================================================================
РАЗДЕЛ 7. ФОРМАТ И СОДЕРЖАНИЕ logs.txt (общий лог всей программы)
===========================================================================
Формат каждой строки: [ГГГГ-ММ-ДД ЧЧ:ММ:СС] [модуль] сообщение
Модуль (кто написал строку):
    [collector]  — сборщик: LOG RESET, START collection symbol=... timeframe=...,
                   ERROR request failed (ретрай/сбой сети хоста),
                   WARNING no candles received from exchange,
                   DONE saved N candles to candles.csv.
    [backtest]   — стратегия: START backtest candles=N ma=(fast,slow) balance=...,
                   DONE trades=N final_balance=... return=...% history saved ...
    [pipeline]   — оркестратор: STAGE START/PASSED, CHECK ... OK,
                   WARNING при любом отклонении этапа (конвейер останавливается).
Уровни внутри текста: ERROR — сбой; WARNING — подозрение/деградация; остальное —
нормальные события. Файл один: очищается и перезаписывается каждым новым запуском
collector, новые лог-файлы не создаются.
